# JSON member attribute conformance

`Program.cs` exercises the actual System.Text.Json internal attribute call paths through test-only unsafe accessors. The helper is not an application registration API. The test compares stock .NET 10 JIT, the replacement JIT and an executed NativeAOT consumer.

The maintained fixture covers raw versus static property inheritance, eager construction and named setters before duplicate errors, constructor/setter exceptions, selected and unused private constructors, closed generic owners, source-generated required JSON properties, and fresh raw arrays. The extended fixture also checks all nine static JSON member attribute reads, a closed generic property and the actionable native error for an unadvertised owner. A custom `PropertyInfo` separately verifies original JIT virtual dispatch.

`Library/Unsafe.cs` intentionally produces two source diagnostics. `UnsafeControl/Program.cs` distinguishes an unused generic argument from a serialized owner whose attribute constructor is actually requested. The unused argument must not gain a JSON owner or attribute factory; the actual serialized request must retain IL2026 and IL3050. These are diagnostic controls, not clean release artifacts.

Current accepted constructor-role execution: `artifacts/json-member-native-v3/independent-input-proof.json` (22 output lines, 0 IL and 0 other warnings, SDK-free execution and exact original/replacement/published-entry JIT parity). Tool48 excludes attributes from unused unannotated struct and hierarchy-only base constructors while preserving the selected KeyValuePair constructor. Native guard controls reject an unadvertised owner, a hierarchy-only constructor request and a FSharp mapping whose flags cannot be proven from metadata. The unsafe differential receipts under `artifacts/json-member-unsafe-domain-v2` retain four genuine IL2026/IL3050 diagnostics only for the serialized unsafe owner. Actual publication uses no IL NoWarn entries; `_TrimmerShowRedundantSuppressions=true` removes the SDK's inert default IL2121 entry in verification profiles. Earlier Tool47 native evidence and the duplicate source-generator hint fixture failure remain preserved.

`artifacts/json-constructor-role-check-v6/frozen48-result.json` compares 25 constructor-selection cases against stock JIT, including compiled FSharp records, unions and special collections. Those FSharp cases establish managed and metadata selection parity only; they do not establish FSharp native support.

The focused proof does not establish full provider readiness or every JSON converter's raw attribute role. Additional checks must preserve evidence and use an immutable successor if another unused role is found.

Tool50's additional converter-role proof is `artifacts/json-member-native-v4/independent-input-proof.json`: 27 output lines, SDK-free, no IL or other warnings, exact stock/replacement/published-entry JIT parity, 179 native inputs and 178 PE/PDB pairs. The native source-generated enum, collection, custom-converter and JsonRequired cases leave unused attribute effects at zero. `RawRoles/Library.cs` and `Program.cs` separately compare actual stock resolver effects for ignored overrides, nonpublic/static/indexer members, invalid ignored types and selected SetsRequiredMembers constructors; their generated operations exclude 17 formerly unused construction factories while retaining real object-required and FSharp-first type effects. `json-member-unsafe-domain-v3` preserves the actual unsafe differential under Tool50.

The inherited static property fixture now requests the actual JSON `JsonPropertyNameAttribute`; raw ProbeAttribute effects retain their separate raw-query tests. A hypothetical arbitrary attribute request through test-only accessors does not establish an upstream JSON read role. Full provider and FSharp native acceptance remain separate.
